# SyncWave

[English](README.md) · **Українська**

[![CI](https://github.com/y-teitelman/SyncWave/actions/workflows/ci.yml/badge.svg)](https://github.com/y-teitelman/SyncWave/actions/workflows/ci.yml)

**SyncWave** — self-hosted сервіс формату watch party для спільного перегляду й прослуховування медіа в реальному часі. Ви кидаєте друзям посилання на кімнату (наприклад, у Discord), вони відкривають його у звичайному браузері, вводять нікнейм — і всі бачать і чують одне й те саме в ту саму мить: один хост керує відтворенням (play, pause, seek), а в кімнати спільна черга. Учасникам нічого не треба встановлювати, а все працює на безкоштовних інструментах.

> **Статус:** рання розробка. Доменне ядро та юніт-тести готові; далі — API, шар реального часу та інтерфейс.

## Технології

- **C# / .NET 10** (LTS)
- **xUnit** для юніт-тестів
- **GitHub Actions** для CI (збірка й тести на кожен push і pull request)
- Заплановано: **ASP.NET Core** (завантаження файлів і стрімінг через HTTP Range Requests), **SignalR** (синхронізація в реальному часі), простий браузерний клієнт, **Cloudflare Quick Tunnel** / **ngrok** для безкоштовного публічного доступу
- Потім, за бажанням: **SQLite / PostgreSQL** + **EF Core**, **Redis**, **Docker**

## Що вже працює

Бібліотека `SyncWave.Core` містить доменну модель і логіку кімнати:

- **Кімната**: код кімнати, список учасників, поточне медіа, позиція та стан відтворення
- **Логіка хоста**: перший учасник стає хостом; коли хост виходить, роль переходить до наступного учасника
- **Скидання порожньої кімнати**: коли виходить останній учасник, відтворення зупиняється, а поточне медіа, позиція й черга очищаються
- **Спільна черга**: перший доданий елемент одразу починає грати, решта чекають у черзі; `PlayNext` рухається по ній і зупиняє відтворення, коли черга порожня
- **Керування відтворенням**: `Pause`, `Resume` і `SeekTo` з перевіркою меж тривалості медіа
- **Типи медіа**: аудіо, відео та YouTube

Ще не реалізовано (див. [docs/NEXT_STEPS.md](docs/NEXT_STEPS.md)):

- Керування багатьма кімнатами та пошук кімнати **за кодом** (`IRoomManager`; код зберігається, але менеджера кімнат ще немає)
- Обмеження керування відтворенням лише **хостом** (зараз будь-хто може поставити на паузу чи перемотати)

## Структура проєкту

```
SyncWave.sln
├── README.md / README.uk.md  # Опис проєкту англійською та українською
├── global.json               # Фіксує версію .NET SDK (10.0.x)
├── .editorconfig             # Спільний стиль коду
├── .github/workflows/ci.yml  # CI: збірка й тести
├── docs/NEXT_STEPS.md        # Навчальний план із підказками
├── SyncWave.Core/            # Доменна модель і бізнес-логіка (без залежностей від вебу чи БД)
│   ├── Entities/             # Room, Participant, MediaItem
│   └── Enums/                # PlaybackState, MediaType
└── SyncWave.Core.Tests/      # xUnit-тести логіки кімнати
```

Заплановані шари: `SyncWave.Infrastructure` (зберігання файлів, зовнішні сервіси) і `SyncWave.Web` (ASP.NET Core API, стрімінг, SignalR-хаб, веб-сторінка).

## Як запустити

Потрібен [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0). Підійде будь-який редактор; репозиторій рекомендує VS Code з розширенням C# Dev Kit.

```bash
git clone https://github.com/y-teitelman/SyncWave.git
cd SyncWave
dotnet build
dotnet test
```
